# Windows 双屏键盘输入回归

当前键盘链路使用独立消息窗口接收后台 Raw Input，不根据桌宠位置、
鼠标坐标或前台窗口所在屏幕过滤按键。鼠标桌面位置另行读取，所以
“鼠标跟随正常”并不能证明键盘订阅正常。

本次修复补齐注册丢失后的恢复：每秒检查进程内的键鼠订阅；订阅消失，
或本接收窗口丢失后台接收标志时，重新订阅对应设备类别。先释放旧的
按下状态，避免恢复后卡键。另一接收窗口持有的注册不会被覆盖；
无法确认注册情况或当前不在正常输入桌面时，不尝试恢复。

这修复了代码中确认存在的恢复缺口，但尚未证明它就是用户反馈的原因。
此次未编译、未运行新增 C 测试，也未完成真实双屏及游戏验证。

## 编译后验证

1. 普通权限启动桌宠，在主副屏各打开一个记事本。桌宠分别放在主屏、
   副屏，各测试两个记事本中的按下、长按、松开和连续输入。
2. 副屏分别放在主屏左侧、右侧、上方；使用不同缩放比例；切换主屏。
   各组合都应响应键盘，鼠标跟随保持正常。
3. 在两个记事本之间切换焦点，打开并关闭桌宠设置，拔插外接键盘、
   断开再接上副屏，锁屏后解锁。确认恢复后无卡键或持续不响应。
4. 在游戏允许后台桌面应用的前提下，分别测试窗口、无边框及全屏模式，
   并在游戏和副屏记事本之间切换。输入应正常送达游戏，桌宠不抢焦点。
   游戏限制后台输入时，不通过提权、输入钩子或模拟输入绕过。
5. 编译 Windows 输入测试目标 `bongo_cat_windows_input_tests` 后，运行
   `ctest --test-dir <构建目录> -R '^windows-input$' --output-on-failure`。
   新增用例覆盖键盘注册丢失、
   后台标志退化、保留鼠标订阅、不覆盖其他接收窗口，以及工作线程恢复。

## 仍能复现时

请用户在同一次运行中，先在主屏记事本连续敲击、松开按键至少 20 秒，
再在副屏重复至少 20 秒，每个阶段保持记事本在前台，并记录大致时间。
之后打开设置的关于页面，点击“打开日志”，复制 `BongoCat.log` 发回。
**先保存日志再重启桌宠**：主进程每次启动会清空上次会话日志。
不需要开启调试模式，也不需要以管理员身份启动。

记录系统和桌宠版本、屏幕布局、问题软件、权限级别，以及同一软件移到
另一屏幕后问题是否随之移动。优先用普通权限记事本区分屏幕因素和软件因素。

日志中的 `[input] Raw Input ownership changed` 表示监听注册发生变化，
`background registration restored` 表示已恢复注册，`recovery failed` 后的
错误码用于定位恢复失败。类别位 `1` 为鼠标，`2` 为键盘，`3` 为两者。
这些日志不记录用户输入内容。注册恢复不等于已收到真实键盘事件。

`[input] receiver` 在启动、退出和运行期间每 10 秒记录一次；
`[input] consumer` 在主循环运行期间每 10 秒记录一次。数值是本进程本次
运行的累计计数，分析时比较相邻记录的增量，不能把累计数量当成当前按下键数。
双屏相关字段只是打印时的快照，不代表整个统计区间的输入都来自该屏幕。

| 字段 | 用途 |
| --- | --- |
| `keys` / `background_keys` / `mouse` | 收到的有效原始键盘包、其中后台键盘包及鼠标包；按键长按重复也计数 |
| `filtered_keys` / `duplicate_keys` | 被规范化过滤的包及重复状态包；增长不一定是错误 |
| `queued_keys` | 成功送入主线程队列的键盘事件；包含清理状态产生的释放事件 |
| `queue_failures` / `wake_failures` | 入队和 SDL 唤醒失败的尝试次数，包含后续可能成功的重试 |
| `invalid` / `device_drops` / `read_failures` | 无效包、设备状态分配失败或达上限、系统读包失败次数 |
| `device_changes` / `devices` | 设备到达和移除通知次数、当前追踪设备数 |
| `owned` / `desktop_unavailable` / `query_error` | 后台订阅归属、输入桌面是否无法访问或不匹配、注册查询错误码 |
| `recovery_error` / `last_read_error` | 最近恢复失败或读包失败的错误码；最后读包错误不会因成功读取而清零 |
| `drained_keys` / `ignored_keys` | 主循环取出的键盘事件数、其中被诊断模式忽略的数量 |
| `mapped_keys` / `unmapped_keys` / `no_model_keys` | 模型按键映射接受、未接受、模型未就绪的事件次数；包含程序内部补发的事件 |
| `frames` / `visible` / `minimized` / `dirty` | 成功提交画面次数及当前窗口、重绘状态；提交成功不保证屏幕实际可见 |
| `monitors` / `foreground_pid` / `foreground_primary` / `foreground_rect` | 当前屏幕数量、前台 PID、前台是否在主屏及所在屏幕边界（左、上、右、下） |
| `pet_position` / `pet_display` / `pet_primary` / `pet_bounds` | 桌宠位置、SDL 屏幕 ID、是否在主屏及屏幕区域（横坐标、纵坐标、宽、高） |

先确认各 `known` 字段再解读位置数据。若副屏阶段 `keys` 不增长，应检查
系统投递、订阅归属及输入桌面；若 `keys` 增长而 `queued_keys` 不增长，
检查过滤、重复状态和入队失败；若已入队但 `drained_keys` 不增长，检查
主循环是否卡住；若已消费，再看模型映射、显示状态和提交画面计数。
日志不会记录具体按键、输入文字、窗口标题或进程路径。

游戏兼容性保持普通 Raw Input 订阅、不注入、不读写游戏内存、不安装驱动、
不模拟输入的边界；这不构成任何反作弊产品的兼容性认证。
